## Architecture and deployment
- `frontend/`: static HTML/CSS/JS with Bootstrap, Flatpickr, FullCalendar from CDNs. Deployed on Vercel (project `hijazi-apartments`, team `ammar-theebs-projects`). Pushing to `main` deploys production; every PR gets a Vercel preview.
- Domains: `hijazi-apartments.com` → 308 → `www.hijazi-apartments.com` (production). Canonicals use `https://www.hijazi-apartments.com/`.
- `backend/`: Node/Express + MongoDB Atlas on Render at `https://api.hijazi-apartments.com`. Apartments, availability and bookings come from the API.
- `frontend/admin.html` is the PMS (noindex). Do not touch it for SEO work.
- Tests: `cd backend && npm ci && npm test` (92 tests; some check frontend files, including that the amenities pages match the data file, that the English twins of about/faq/reviews match their Arabic pages, and that every photo-album room has contents).
- Workflow: earlier work went branch → PR → Vercel status → squash merge to `main`. On 2026-11-12 the owner chose a direct push to `main` without a PR, and asked for it again on 2026-11-13, 15, 16 and 18. On 2026-11-20 he gave standing permission: push to `main` and update this file without asking each time, and take whatever steps the work needs. Still never open a PR unless asked, and still explain large or look-changing changes in the reply.
- On Windows the checkout has CRLF line endings, so the test "amenities pages are in sync" fails locally until `node scripts/build-amenities.js` is run; that run changes line endings only (empty `git diff`), so restore those three files afterwards and do not commit them. Exception: if you edited one of them yourself (e.g. a version bump), do not `git checkout` it, because that also undoes your edit (this happened on 2026-11-18 with `main.js?v=12` on the amenities pages); just commit it, since the line-ending change does not show in git.

- Admin passport scan and reservation form:
  - `js/passport-mrz.js` parses MRZ text (TD3 passports, TD1/TD2 ID cards), checks check digits, fixes common OCR errors and holds the country table (code → country name and nationality). `js/passport-scan.js` runs Tesseract.js 7.0.0 in the browser (pinned on jsDelivr with SRI on the main script, loaded on first use). `js/reservation-form.js` draws the form on `images/reservation-form-template.webp` with the self-hosted font `fonts/barlow-semi-condensed-500.woff2` (OFL). All three are tested in Node; scripts load in `admin.html` at `?v=1` (`reservation-form.js` at `?v=2`).
  - The passport photo is never uploaded or stored. Only the text goes in `booking.guestDocument`, which has `select: false`: the booking list never returns it, only `GET /admin/bookings/:id` does, and it is never written to the activity log. The public booking route cannot set it.
  - MRZ has no place of birth, issue date or address. Place of birth is typed by the owner. The issue date is filled only when a printed date fits the passport validity exactly (N years or N years minus one day before the verified expiry). The address defaults to the issuing country name.
  - Required vs optional guest fields: only apartment, check-in and check-out block saving (frontend `required` and `POST /admin/bookings`). After a scan, empty essential fields get the «ناقص» mark as a warning only (it does not block saving): full name, nationality, passport/ID number, date of birth, phone (`ESSENTIAL_GUEST_KEYS` plus name and phone in `applyPassportScan`). Gender, passport issue and expiry dates, place of birth, address and email carry a grey «اختياري» tag (`OPTIONAL_GUEST_FIELDS`, class `field-optional`) in both the add and the edit forms and are never marked «ناقص». «تحقق» marks are unchanged. The owner chose warning-only, not enforcement (2026-11-16).
  - Payment fields on a booking: `nightlyRate`, `securityDeposit`, `amountPaid` (null means automatic: deposit 200, paid = rent + deposit) and `paymentMethod` (default CASH).
  - In the admin add and edit forms the four money fields are linked (`syncPrices` in `admin.html`, 2026-11-16): nightly rate → rent = rate × nights; rent → rate = rent ÷ nights; deposit → paid = rent + deposit; paid → rent = paid − deposit and rate = rent ÷ nights; date or apartment change recalculates from the nightly rate. They are `type="text" inputmode="decimal"` parsed by `parseMoney`, which accepts decimals, "," or "٫" and Arabic digits; an invalid amount stops the save with a message. Rates are rounded to 0.01.
  - Booking reference: `HA-DDMMYYYY-<apartment number>` from the check-in date. It is computed, not stored, so it changes if the apartment or check-in date changes.
  - Text positions on the form are `FIELD_LINES` in pixels on the 1536×1024 template. If the owner changes the template design, update them.
  - Admin dialogs cap their height to the window and scroll inside. The page's global input and dialog styles use `!important`, so new admin styles often need it too.
- Animated page background (`.apartments-page-bg` in `apartments.html`, `.booking-page-bg` in `booking.html`) and the apartments header background: every layer is a `<canvas data-fx="...">` painted once by `js/cosmic-bg.js` (loaded right after the page header, `?v=1`); the page CSS only sets size, position and animation. Animate only `transform` and `opacity` there. Soft layers (base gradient, smoke, orbs, shine, header) are painted at 1/6 resolution and stretched; dust and twinkle dots at up to 1.5×. Reason: a normal CSS layer costs a full-resolution screen of GPU memory each, and too many of them made scrolling show blank/pixelated tiles. To change a shape or colour, edit the painter in `cosmic-bg.js`. The booking header background is static (its animation never ran, because `background` there is `!important`).
- Do not put `backdrop-filter` on an element inside another element that already has it (cards, navbar): it costs a GPU layer and blur per element and its only visible effect is a darker tint. Put the tint in the background colour instead (done for `.card-price-box`, `.card-top-badge`, `.navbar-collapse`, `.lang-switcher`).
